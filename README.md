# Классификация изображений кошек и собак

В ноутбуке вы соберёте датасет, сохраните его версии в DVC, сравните модели в MLflow и выберете формат ONNX. Сайт с выбранной моделью запускается отдельно в Docker.

## Первый запуск

Откройте терминал в корне проекта, где лежат `requirements.txt` и ноутбук. Команды ниже проверены в Bash с Python 3.12. Для раздела версионирования нужен Git.

**1. Создайте и активируйте окружение.** Следующие команды выполните в том же терминале.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

**2. Установите зависимости.** В `requirements.txt` перечислены JupyterLab и библиотеки для всех шагов работы.

```bash
python -m pip install --no-cache-dir -r requirements.txt
```

**3. Откройте ноутбук.** Запустите JupyterLab в активированном окружении. Команда откроет [ноутбук](<Кот или собака.ipynb>) в браузере.

```bash
python -m jupyterlab "Кот или собака.ipynb"
```

Выполняйте ячейки сверху вниз. Первая ячейка удаляет рабочую папку `data/` вместе с локальной историей Git, черновиком разметки и результатами предыдущего прогона. Следующие ячейки собирают фотографии заново.

Для ручной проверки меток в разделе «3. Инструмент для разметки» выполните ячейки до «Запускаем разметчик» включительно. Проверьте метки в открывшейся форме и выполните следующую ячейку, чтобы сохранить `data/annotation/labels_reviewed.json`.

## Повторный запуск

В новом терминале откройте корень проекта, снова активируйте окружение и запустите ноутбук.

```bash
source .venv/bin/activate
python -m jupyterlab "Кот или собака.ipynb"
```

## Данные

Git хранит историю файла `dataset.dvc` с тегами `dataset-v1` и `dataset-v2`. DVC по этому файлу восстанавливает фотографии и метки в `data/dataset/`. Хранилище `dvc_remote/` лежит рядом с рабочей папкой и подключено под именем `dataset-storage`. Ручные исправления меток текущего прогона хранятся в `data/annotation/draft.json`.

## Просмотр результатов в MLflow

После обучения откройте отдельный терминал в корне проекта, активируйте окружение и запустите MLflow. Он прочитает результаты из базы `data/training_mlflow.db`.

```bash
source .venv/bin/activate
mlflow server --backend-store-uri sqlite:///data/training_mlflow.db
```

Откройте [MLflow](http://127.0.0.1:5000), выберите эксперимент `cats-dogs` и вставьте фильтр серии из ноутбука. После сравнения FP32 и INT8 замеры каждого раунда доступны в артефакте `inference/comparison.json` у запуска победителя. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

## Итог проверенного прогона

На валидации победила ResNet18 с macro-F1 **0,617**. INT8 был быстрее в **10 из 12 раундов**, FP32 в двух. Диапазоны времени пересеклись. Выбрали **INT8** по меньшей медиане времени на CPU (**9,80 мс** у INT8 и **10,23 мс** у FP32), файлу меньшего размера (**10,8 МиБ** вместо **42,6 МиБ**) и тому же F1.

Результат на отложенном тесте указан в разделе «Итог». [Открыть ноутбук](<Кот или собака.ipynb>)

## Сборка и запуск сайта в Docker

Выполните ноутбук до конца раздела «Экспорт в ONNX и квантизация». В `deployment/app/bundle/` появятся `model.onnx` и `metadata.json`. Для следующих команд нужен работающий Docker Engine. Запускайте их из корня проекта, где лежит `requirements.txt`.

**1. Соберите образ** по [Dockerfile](deployment/Dockerfile).

```bash
docker build -f deployment/Dockerfile -t cats-dogs:local .
```

**2. Запустите контейнер.** Порт 8010 на компьютере ведёт на порт 8000 контейнера.

```bash
docker run --rm --detach --name cats-dogs -p 127.0.0.1:8010:8000 cats-dogs:local
```

Откройте [форму загрузки](http://127.0.0.1:8010) и загрузите фотографию.

**3. Остановите контейнер** после проверки.

```bash
docker stop cats-dogs
```
